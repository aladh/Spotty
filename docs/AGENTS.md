# Documentation

- Keep one canonical owner for each topic, update it when behavior changes, and remove stale guidance.
- Document intent, usage, and non-obvious constraints. Link to implementation instead of duplicating
  mechanics; omit task and review history.
- Add instructions only for recurring risks that cannot be enforced or discovered elsewhere. Omit
  inventories, implementation maps, exhaustive state or test catalogs, and copies of linked contracts;
  prefer correcting or deleting guidance to adding more.
